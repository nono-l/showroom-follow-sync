# SHOWROOM フォローオンライブ同期

人間と、あとから入った AI の両方が読める説明。

## この拡張がやること（だけ）

1. ログイン中に `https://www.showroom-live.com/api/follow/onlives?genre_id` を取る
2. 配信中なのにタブが無い部屋を開く
3. タブはあるが配信が終わった部屋を閉じる
4. 開いている配信タブを、公平に N 秒ずつ前面へ出す
5. 配信ルームタブは SHOWROOM 専用ウィンドウへ集める。ウィンドウ ID は session に覚え、生きていれば再利用し、閉じていたら作り直す
6. 次の取得タイミングは `max(開いている配信タブ数 × N秒, 下限秒)` のあと
7. 同時オープン上限に達したら、視聴時間が長い部屋を「今は開かないリスト」へ移してタブを閉じる
8. 同時配信数が減ったら、無視リストから 1 件ずつ戻す

csrf_token はブラウザ起動ごとに1回。消えていたら取り、あれば使う（chrome.storage.session）。

旧「人間をやめるぜ」拡張の移植ではない。ギフト・通知・jQuery は扱わない。

## ファイル分担

- `sw.js` … Service Worker の入口。本体ロジックは持たず `engine-1.js` と `engine-2.js` を読む
- `engine-1.js` … 定数・状態・タブ/ウィンドウ/通信の部品
- `engine-2.js` … 同期・巡回・イベント接続。`engine-1.js` の関数を前提にする
- `offscreen.html` / `offscreen.js` … 秒単位タイマーだけ
- `content.js` … SHOWROOM タブ上で Cookie 付き fetch
- `popup.html` / `popup.js` … 設定と状態表示
- `manifest.json` … Manifest V3

## コーディング方針（何も知らない AI 向け）

このリポジトリは、別セッションの AI が途中から読んでも迷わないことを優先する。
コードを読む相手は「昨日の会話を覚えていない AI」だと仮定する。

### コメントに書くこと

- **何をしているかより、なぜそうしているか** を書く。
- 関数・ファイルの先頭で、役割・やらないこと・前提・失敗して捨てた案を短く書く。
- 一見不思議な行（Cookie を SW から取らない、offscreen に storage を置かない、専用ウィンドウを session に覚える、など）には、制約か事故の理由を残す。
- 名前で分かる処理（`return null` など）にはコメントを付けない。
- コメントは日本語。人間と AI の両方の第一言語を日本語に揃える。

### コメントに書かないこと

- コードを言い換えただけの説明（「変数に代入する」など）
- 将来やるかもしれない機能の予告
- 旧拡張「人間をやめるぜ」の思い出。このリポジトリは移植ではない

### 変更するとき

- 意図が変わったら、先にコメントを直してからコードを直す。
- コメントとコードが食い違っているなら、コメントが古い。コードに合わせてコメントを直す。
- 新しい制約を踏んだら、その場に一行で理由を残す。Issue やチャットにしか書かないと、次の AI は見えない。
